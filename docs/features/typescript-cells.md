# TypeScript cells

A cell is one model-authored TypeScript source executed in the persistent kernel that a Baton Session owns. `@batonfx/repl` owns the generic contract; the root export is contracts only, and `@batonfx/repl/bun` is the only module with process dependencies.

- An agent advertises exactly one cell tool, `typescript`, whose parameters are exactly one bounded string field named `code`. Because one namespace is shared, `CellTool.scheduling` is always `maxConcurrency: 1` with no parallel-safe tool, so every cell is an authored-order exclusive barrier.
- Success is `CellResult`: the formatted value, bounded stdout and stderr, duration, the kernel epoch, and the exact truncation facts per channel.
- Failure is the closed `CellFailure` union with `failureMode: "return"`, so a failed cell re-enters the model as an observation rather than failing the run. `CellExecutionFailed` means the cell threw and the namespace survived; `KernelUnavailable` means nothing was evaluated; `KernelProtocolViolation` means the kernel broke the cell protocol; `CellOutcomeUnknown` means the cell may or may not have committed and a host must resolve it explicitly.
- `CellEvent` is the closed union of `KernelStarting`, `KernelReady`, `Stdout`, `Stderr`, `Result`, `Display`, `OutputTruncated`, `StateRestored`, `StateLost`, and `KernelRestarted`. Every event carries its `cellId` and a cell-local `sequence` that starts at 0 and increases by exactly one per emitted event; `Cell.validateSequence` rejects a gap, a repeat, a non-zero start, and interleaving from a second cell. The cell route emits one `ToolContext` progress update per event, so a host observes cell lifecycle through the existing tool-progress seam.
- `KernelProfile` identifies one kernel epoch by contract version, protocol version, pinned runtime identity and digest, bindings digest, workspace paths, ingestion limits, and trust mode. It declares no secret-bearing field — only identifiers, digests, paths, and bounds — and unknown keys are dropped from both the encoded form and the digest, so a host cannot widen it by attaching extra data. The content of its free-text identifier and path fields is host-supplied and is not scanned or redacted; a host that embeds a secret in a path or a runtime name persists and renders it. A foreign protocol version fails to decode. `KernelProfile.digest` is the content-addressed identity, and a changed profile requires a new epoch rather than reuse.
- `KernelPool` is the kernel lifecycle port: `execute`, `inspect`, `interrupt`, `restart`, and `close`, all keyed by Session identity. `KernelStateStore` is the best-effort snapshot port whose manifest names every binding restored by value, source, or import replay and every binding dropped with its reason. `HostBindingRegistry` is the seam by which a host mounts named Schema-typed modules into the kernel namespace; duplicate module or operation names are rejected at mount, host failures are tagged so a cell can discriminate them as data, and schema faults are reported per stage.
- Kernel state is working memory, never durable authority. Baton operations, events, Session entries, and children remain the only truth; a restart reports exactly what was restored and what was lost; and an uncertain cell is never replayed.
- `TestKernel` supplies an in-memory `KernelPool` and `KernelStateStore` so hosts, projections, and decoders exercise the contract without a worker process.
