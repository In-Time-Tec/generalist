# BatonFX Context

This file owns BatonFX vocabulary, ownership, and system boundaries. Keep implementation details and provider-specific examples out unless they clarify a stable concept. Current behavior lives in `docs/features/`.

## Positioning

BatonFX is an Effect-native agent framework over `effect/unstable/ai`. `@batonfx/core` is the standalone process-local model-turn loop; `@batonfx/runtime` optionally owns durable addressable Runs, replay, waits, cancellation, children, and workers. Applications compose either boundary as Effect layers on their own models, tools, storage, and interfaces. Core depends on `effect` only and never imports Runtime storage or lifecycle contracts.

## Domain model

- **Agent**: an agent definition value (name, instructions, toolkit, model selection, memory key, turn policy, tool scheduling policy, and metadata) carrying its own defaults. Its default model, when present, is the visible `model` selection resolved by `ModelRegistry`; registry-free runs keep `LanguageModel` in the requirement channel and provide its layer at the run boundary. `Agent.make` builds it; `Agent.stream` streams the model-turn loop and `Agent.generate` folds it to a terminal result. Setting `RunOptions.output` adds one terminal structured-output turn. An Agent is not a user, bot, or account.
- **Turn**: one model call plus scheduled execution of the framework tool calls it emits. Parallel-safe calls may run with the Agent's bound; unlisted calls are authored-order exclusive barriers, and results re-enter the model in authored order. Turn 0 always runs; follow-up turns re-feed tool results via `Ai.Prompt.fromResponseParts(...)`.
- **TurnPolicy**: a plain, `Schedule`-inspired Effect program (not a service) that decides whether to run another turn when tool results are pending. Its requirements remain visible on the Agent run, evaluation fails with `TurnPolicyError`, and stops carry a serializable `StopReason`. `forever`, finite `recurs`, `untilToolCall`, and fully portable `both` values carry inert serializable snapshots for durable hosts; non-finite recurrence counts and `make` remain opaque runtime policies. Default `forever`: no framework-imposed follow-up cap, while a turn with no pending tool results still completes the run naturally. An explicit `Forever` snapshot is distinct from an absent snapshot (an opaque policy) and from a legacy record with no policy field.
- **ToolExecutor**: the tool-call execution seam. `execute(request) => Effect<Outcome, FrameworkFailure | RemoteRetryMisconfigured>` where `Outcome` is `Success | DomainFailure | Suspend`. Domain failures retain decoded and schema-encoded values; schema, handler-boundary, routing, placement, and authorization failures are schema-backed framework errors. `RemoteRetryMisconfigured` reports retry-policy configuration faults before they become placement failures. Default `layerToolkit` runs the toolkit's own handlers in-process; hosts swap in their own.
- **ToolContext**: the per-call ambient service provided while a framework-executed tool is running. It carries `sessionId`, tool-call and stable operation identity, interruption, progress, and, when supplied by a durable host, authoritative Run/root identity, execution attempt, admission time, and deadline.
- **ToolOutputStore**: the optional spill seam for oversized successful tool outputs. Baton can store the full output out of context and re-feed a bounded inline `ToolOutput` value with `outputPaths`; absent or no-op stores preserve inline results unchanged.
- **Approvals**: the single resolution seam for permission asks and `Ai.Tool.needsApproval`. `resolve(Pending) => Effect<Resolution>` where `Resolution` is `Approved | Denied | Pending`; an explicit `Approved.remember` rule is the only path that updates RuleStore. The run default auto-approves.
- **AgentEvent**: the closed union of loop events hosts observe and optionally persist (`ModelPart`, `TurnStarted`, `TurnCompleted`, `StructuredOutput`, `ApprovalRequested`, `Completed`, tool execution and progress events).
- **AgentError**: a `Schema.TaggedErrorClass` for general loop failures and wrapped external failures. Policy stops, middleware violations, suspensions, and tool framework failures retain their own typed run errors.
- **AgentSuspended**: a typed error on the stream's error channel signalling the run did not finish and must be re-entered via `RunOptions.resume` once the host resolves the suspension `token`. Reasons: `tool-wait` (from a `Suspend` outcome) or `approval` (from a `Pending` decision).
- **Permissions**: the required decision seam consulted once for every framework-executed local tool call. Remembered RuleStore rules overlay the base decision with the same last-match matcher and preserve the base reason/token as fallback. Runs provide allow-all and owned in-memory RuleStore defaults; asks and `needsApproval` share one Approvals resolution and suspension path.
- **ModelRegistry**: the provider-agnostic registry that maps a model selection to a concrete Effect AI `LanguageModel` layer. Missing registrations fail typed, not silently.
- **Providers**: the optional `@batonfx/providers` helper package that adapts upstream `@effect/ai-*` providers into `ModelRegistry` registrations and exposes embedding layers over Effect AI's `EmbeddingModel` tag. Core remains provider-agnostic.
- **TestModel**: the scripted Effect AI language model in `@batonfx/test`. A stateful fixture owns one atomic response cursor, captures normalized provider requests, and exposes direct and `ModelRegistry` layers for deterministic prompt, tool, steering, queue, compaction, structured-output, and retry tests without credentials.
- **Agent Program**: exact model-authored JavaScript source paired with a pinned sandbox, pinned input/output schemas, a version-2 allowlisted tool, named-step, and exact-Agent closure, and resource budgets. `AgentProgram.run` schema-encodes input, delegates encoded execution to `ProgramHost`, and schema-decodes the encoded result. A durable Agent may carry `ProgramAuthority`, the maximum source size, sandbox, schemas, capabilities, and budgets that its Runtime-owned `code_mode` tool can narrow into one exact child Program.
- **ProgramBindings**: the host-owned live implementations behind a Program manifest. Tool and named-step bindings carry executable input/output codecs, exact pins, replay policy, authorization, and handlers; Agent bindings carry an exact Agent pin, input codec, replay policy, authorization, and an executor that reports text, turns, and token usage. Source cannot supply or inspect bindings.
- **ProgramHost**: the sole owner of Program execution. `layerDirect({ sandbox, bindings })` enforces exact manifest closure and pins, every capability codec, host authorization, operation/member identities, deterministic bounded Agent concurrency, and direct-run budgets before delegating source evaluation. Durable hosts implement the same encoded contract without using process-local budget or replay state.
- **ProgramCapabilities**: the encoded operations visible only inside an Agent Program sandbox protocol: `callTool`, `callStep`, `runAgent`, `mapAgents`, `fanOutAgents`, and structured logs. Source never receives tool handlers, Agent values, credentials, stores, Runtime services, replay policy, authorization policy, or ambient host objects.
- **SandboxExecutor**: the scoped source-evaluation seam supplied to a ProgramHost by a host that can provide the required isolation. Core exports only trusted test constructors and Layers and makes no security claim for them; it ships no production JavaScript sandbox.
- **ModelCatalog**: the optional provider-package service for static model metadata such as context windows, output limits, pricing, and modalities. It lives in `@batonfx/providers`; core never depends on it.
- **MCP OAuth**: the `@batonfx/mcp` authorization lifecycle for authenticated remote servers. Baton owns discovery, PKCE, callback exchange, refresh integration, and typed failures; hosts own browser/callback UI and redacted token persistence.
- **MCP BatonTools**: the scoped `@batonfx/mcp/baton` route result that keeps one discovered toolkit, its Effect AI handlers, the Baton `ToolExecutor` layer, and the owning MCP connection lifetime together.
- **ModelResilience**: the optional policy for one logical model call. It resolves error-part payloads to typed `AiError` values, classifies failures, supplies the provider retry schedule, bounds invalid-tool-call corrections, and may set an explicit stream-idle deadline. Every raw provider invocation is an instrumented attempt under that call. Provider errors are failures, not output; streamed turns retry or correct only before reasoning, text, or a validated tool call escapes. Invalid-tool correction is driven only by Baton's tool-parameter validation boundary, using the active provider's registered JSON Schema compiler; generic model output decoding failures never masquerade as tool failures.
- **ModelMiddleware**: the interceptor seam for everything going into (`transformPrompt`) or out of (`transformPart`) the model — PII scrubbing, prompt-injection screening, output filtering, logging. Ships a `layerIdentity` default and no built-in filters.
- **Guardrail**: ergonomic `ModelMiddleware.Middleware` combinators for input validation, prompt/output regex redaction, and output filtering. Guardrails are not a separate subsystem; they compose through `ModelMiddleware.layer([...])`.
- **Instructions**: the ordered context-source registry. `openEpoch` renders every source once into the run's system-message baseline. Baton does not inject dynamic updates. Filesystem, skills, and memory sources are contributed by later packages/seams.
- **Memory**: the optional recall/remember/forget seam. `RunOptions.memory.key` is host-chosen; recall inserts one structurally provenanced user message after the system message and before the run prompt; remember runs after completed turns over a memory-specific transcript projection that excludes recalled context; forget is a host-requested lifecycle cleanup operation for a whole key or one remembered item id. Non-durable working-memory and semantic-recall implementations live in `@batonfx/memory`; durable memory remains host-owned.
- **Continual harness**: the versioned agent-guidance store of prompt notes, memories, skills, and subagent specs, plus the refinement events that change it. `@batonfx/harness` owns the generic engine: entry identity and versions, atomic proposals with exact before/after entries, rollback proposals, scope overlay where an inner scope wins by kind and id, bounded prompt-overview formatting, and the content-addressed snapshot a host pins into an executable registration. Store locations, scope policy, and refine flows stay host-owned.
- **SkillSource**: the optional source seam for agentskills.io `SKILL.md` skills. Startup context receives selected listings only; bodies load lazily when the model calls Baton's `activate_skill` tool. Concrete filesystem and manifest-backed HTTP, S3, and GitHub adapters live in `@batonfx/skills`, not core; hosted catalogs are Baton integration contracts rather than Agent Skills standard protocols.
- **Cell**: one model-authored TypeScript source executed in the persistent kernel that a Baton Session owns. `@batonfx/repl` owns the generic contract: the single `typescript` tool with exactly one bounded `code` parameter, `CellResult`, the closed `CellFailure` union, the closed `CellEvent` union ordered by a cell-local monotonic sequence, the `KernelProfile` that identifies one kernel epoch and declares no secret-bearing field, and the `KernelPool`, `KernelStateStore`, and `HostBindingRegistry` ports. The root export carries contracts only; `@batonfx/repl/bun` is the only module with process dependencies. Kernel variables are working memory: Baton operations, events, Session entries, and children remain the durable authority, a thrown cell is model input rather than a run failure, and an uncertain cell is never replayed. Host capability semantics, store locations, trust policy, and presentation stay host-owned.
- **Session**: an append-only conversation entry log with a current leaf pointer for branch navigation, and the authority for model-facing history. `Session.buildContext(path)` is the pure projector from a root-to-leaf path into an `Ai.Prompt`. A Run seeds its Chat from the active Session path rather than carrying a conversation across turns, and `@batonfx/runtime` provides a durable SQLite Session per session identity. Session entries are conversation only: execution records never enter model context, the system message is derived per Run, and a spawned child derives its own session identity. Transport does not own session execution or history.
- **Transport**: the encoding and connection boundary for Runtime-owned RunEvents. SSE and WebSocket carry exclusive replay cursors, snapshots remain separate inspection resources, and disconnecting an observer never cancels a Run.
- **Steering**: the optional live-input seam with two queues. Direct Agent steering is process-bound. Runtime steering is a durable per-Run FIFO inbox: admission is idempotent, reads are claim-scoped and non-destructive, and the exact observed batch is consumed atomically with the next model operation checkpoint. Steering input drains after tool results and before the next model turn; follow-up input drains only when the run would otherwise complete.
- **Compaction**: the optional context-shrinking seam for long runs. A strategy decides whether to compact, chooses a safe session cut point, and summarizes old context into a checkpoint after first trying tool-output microcompaction. A durable Agent manifest pins one compaction service, one summary model, the context window, and reserved tokens; the service registration owns only bounded keep-recent, strategy, and summary-prompt identities. When Session is active, every changed projection commits through one idempotent checkpoint whose exact projected history is authoritative for both live Chat and point-in-time Session rebuilds. A checkpoint is self-contained: projection never reads entries before it.
- **Chat persistence seam**: setting `RunOptions.persistence` runs `Agent.stream` or `Agent.generate` on a persisted `Ai.Chat` instead of a fresh one and exposes `Chat.Persistence` in the run requirements. Baton delegates all chat storage to `effect/unstable/ai`'s `Chat.Persistence`; it adds no chat store of its own.
- **Tool output spill seam**: `ToolOutputStore` stores oversized tool outputs out of context when present and when `RunOptions.toolOutputMaxBytes` is exceeded. It is non-durable in core; durable blob stores belong to the Runtime host.

## Invariants

- Baton depends on `effect` only. It never imports from any durable runtime's schema, event log, or database. In this repo the rule is enforced by the `no-relayfx-imports` ast-grep rule.
- Payload vocabulary is `Ai.Prompt`/`Ai.Response`; core messages mean conversational content, while Runtime `Message` is the sole addressed admission value. Baton does not add a competing envelope vocabulary.
- Every exported symbol is `@experimental` while `effect/unstable/ai` is itself unstable.
- Public construction verbs follow one canon: `make` constructs an in-memory value, `register` records it for later lookup, and `start` is reserved for beginning a durable host `Execution`. `create` is not a synonym for `make` or `register`.
- Public APIs use package-root module namespaces. Layer constructors are `layer` plus noun-after-`layer` variants such as `layerMemory`, `layerNoop`, `layerIdentity`, or `layerConfig`; parameterization belongs in `layer(options)`, and alias exports do not exist.
- Errors that cross a service boundary are `Schema.TaggedErrorClass` values tagged `@<scope>/<package>/<Name>` whose class name states the failure condition without a forced `Error` suffix.
- Baton's `Suspend` tool outcome, `AgentSuspended` error, and suspension token remain agent-loop concepts. A durable host maps a Baton suspension to its `Wait` concept only at that boundary.
- Every post-middleware tool-call ID is unique within its model response. Duplicate transformed IDs fail typed before the duplicate can initiate authorization, execution, or persistence.
- Resume is bound to the sole unresolved authoritative suspension checkpoint. Baton persists the suspension token and authorization snapshot on the transformed call, rejects a missing, stale, duplicate, or mismatched suspension with `ResumeMismatch`, and performs no resumed side effect before that comparison succeeds.
- No `Date.now()` or raw platform time/concurrency/randomness — use Effect primitives.
- Pending tool results are never silently dropped: a `Stop` policy with pending results fails the run.
- Completed framework tool results enter Chat exactly once in call order before Session synchronization, Memory retention, policy evaluation, persistence, and `TurnCompleted`; follow-up turns consume that checkpoint without appending the results again.
- Permission policy is optional through concrete run defaults: absent services use allow-all Permissions, auto-approve Approvals, and an owned in-memory RuleStore.
- Instructions context baselines are opened at run start. Baton has no automatic dynamic-instruction update contract. TurnPolicy instruction overrides are independent: the policy prepends one system message to the selected follow-up prompt, which `Ai.Chat` then retains in transcript history.
- SkillSource is optional and standalone. Absent `SkillSource`, the Agent loop does not advertise skill listings or the `activate_skill` tool.
- Memory is optional and host-chosen. Baton never derives a memory subject; hosts pass either `Agent.make({ memory })` as an agent default or `RunOptions.memory.key` for a run-specific override.
- Memory forget is host-requested cleanup. Baton never infers memory retention or calls forget from the agent loop. `ForgetInput.id` narrows cleanup to one implementation-owned memory item within the exact key; omitting it drops the whole key.
- Recalled memory context carries structural `memoryRecall` origin in Chat and Session framing. Memory retention projects that origin out without comparing message content; identical user-authored content remains retainable.
- Provider helpers are optional and standalone. Core never imports provider SDKs; provider dependencies live in `@batonfx/providers`.
- Steering is optional. Absent `Steering` preserves current turn and completion behavior exactly.
- Compaction is optional. Absent `Compaction` preserves current turn, session, and completion behavior exactly.
- Durable compaction has one owner per setting: the Agent manifest owns context window and reserve tokens, the compaction service registration owns keep-recent and strategy/prompt identities, and the summary-model registration owns opaque model reconstruction. Recovery never substitutes current configuration.
- Dynamic Program admission exists only beneath an Agent manifest carrying `ProgramAuthority`. Runtime injects `code_mode`, deterministically admits one exact Program child per tool call under the existing root Run, and requires the root registration catalog to cover every authority pin. Applications reconstruct the pinned sandbox, codecs, and bindings through `ExecutableResolver`; Baton ships no production sandbox.
- Session-backed compaction commits the Session checkpoint before applying its exact projection to Chat. Checkpoint identity is stable across retry, store append is idempotent, and Session paths rather than projected message counts define synchronization progress.
- Session context is derived from a root-to-leaf path, not stored separately.
- `TurnPolicy` is a plain value, not a service — agents carry their own default like `Schedule` values.
- Turn policy requirements remain visible in Agent run requirements, policy failures remain typed, and successful non-limit stops are never reported as `TurnLimitExceeded`.
- A `TurnPolicy` snapshot describes built-in constructor data only. It never serializes a decision function, Effect, Layer, or service and does not change standalone decision semantics.
- Every behavior-bearing seam exposes a `layerTest` or `layerMemory` so tests swap implementations through Effect layers.
- Transport never owns Run execution, event persistence, subscriber truth, or a parallel lifecycle vocabulary. Runtime remains authoritative for replay, lag failure, terminal facts, and cancellation intent.
- Runtime completion and steering admission are transactionally ordered. Terminal completion rejects later steering; accepted pending steering makes completion return to ExecutionHost continuation instead of stranding the inbox.
- Feature documents record current behavior and relied-on rules. Decision and tradeoff documents explain only choices whose reasons or costs remain useful.
