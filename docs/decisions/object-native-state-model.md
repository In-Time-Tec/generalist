# Object-native state model

Status: implementation decision and reconciliation inventory. `PLAN.md` remains the governing contract. This document records the object-native state boundary, the durable protocol currently present, the boundaries that are intentionally outside `RuntimeState`, and the evidence that is safe to carry into the next integration phase. It is not a claim that the current implementation or all migrated suites are complete.

## Decision

The canonical state of a run is a versioned set of domain records inside one bounded object-store partition (`environment`, `tenant`, `partition`). An authorized command has one durable commit boundary: it is identified by its exact command input, produces a deterministic state transition, and records a receipt. The receipt is the retry/reconciliation authority; a caller timeout is not evidence that the transition did not commit.

The object journal is authoritative. A journal head contains the committed sequence, the logical state digest, the state value, and the retained receipt history needed to reconstruct a complete gap-free prefix. Object listing is paginated and unordered, so a listing or a process-local head hint is never authority. Reconstruction decodes the persisted value strictly, replays deterministic state transitions only, and performs no provider call, callback, process launch, publication, lease takeover, or other external effect. Activation is the separate live-owner operation: it establishes ownership, heartbeats, and takeover/fencing after lease expiry.

A same-partition command can atomically update a run tree, its colocated Session state, operation records, checkpoints, lifecycle events, receipts, and other records in the state value. A model completion, for example, must publish the operation result, Session entry, run event, checkpoint/continuation, and completion receipt as one logical transition. Fan-out admission and aggregate bookkeeping use the same boundary, while each member remains an independently committed run.

Cross-partition work is not presented as a distributed transaction. External child placement, sender obligation, receiver admission, settlement, and acknowledgement are separate durable commands joined by immutable identifiers, digests, and reconciliation. Publication is after commit; process-local subscriber/publication queues are delivery machinery, not recovery authority. Artifact writes likewise use durable object references and receipts rather than treating an in-memory publication as the artifact itself.

Fork and rewind copy an exact committed prefix and retain the discarded suffix as history/branch state. They do not redispatch an inherited provider operation. A branch gets a fresh operation namespace for new work, while copied model responses and interrupted responses remain self-contained through validated Session-entry/event references and digests. Source budget is not refunded by a branch; child reservations and consumed cost remain auditable.

`packages/generalist/src/runtime/state/state.ts` is still a transitional implementation inventory, not the final wire contract. The v1 cutover must retain the domain facts below while removing any dependence on old SQL readers, compatibility decoders, or process-local state as authority.

### Durable execution checkpoint

`core/durable/loop-driver-state.ts` is the durable execution seam beneath `Run.checkpoint` and `Run.suspension`. It records the logical operation ID, Session identity, pending operation kind/key/input/replay policy, model-call ordinal, control/handoff state, tool-batch checkpoint, hook and gate checkpoints, task items, capability checkpoint/taint, artifact checkpoints, and post-commit/terminal state. `pending.input` is intentionally `Schema.Unknown` at this generic layer; each operation boundary must decode it with its v1 domain codec. The checkpoint is a replay decision and evidence record, not permission to call a provider again without the operation's replay policy.

Model completion stores a self-contained reference containing operation, turn, model-call/attempt IDs, attempt fence, Session parent/entry identity, and a digest over the exact unsigned content. `model-response/commit.ts`, `model-response/interrupted.ts`, and `store/fork/model-response.ts` validate that reference against the source operation, event, and Session entry before copying it. Tool output is bounded inline content plus optional durable object paths; a copied tool completion must preserve the exact command identity needed for continuation.

Executable manifests, instruction snapshots/registrations, capability sources, hook chains, gate decisions, and kernel profiles are dependencies of execution rather than arbitrary mutable host configuration. Their durable pins must be secret-free, content/version identified, and available to reconstruction. Capability sources and hook/gate outcomes are evidence; they must not be silently regenerated from the current host.

## Atomic command boundaries and recovery

* **Journal commit.** `durability/internal/runtime.ts` prepares and encodes the command input, then commits it through `journal.commit`. The transition sees one decoded state and returns deterministic patches plus a receipt. Reconciliation of an existing command happens before a fresh transition; fresh observations do not alter command identity.
* **Same-partition projection.** Run, Session, operation, event, checkpoint/continuation, idempotency, budget, and relevant index changes share the command commit when the operation requires them. A successful model response is not complete until the Session entry, operation record, lifecycle event, and checkpoint are committed.
* **External protocol.** Sender obligation/reservation, receiver admission, settlement, acknowledgement, and discovery are separate commits joined by exact IDs/digests. Reconciliation must scan outstanding obligations when a notification or catalog entry was lost.
* **Publication.** State commit precedes external publication. Before-publication, after-publication-lost-ack, and unreadable-publication outcomes must resolve from receipts and operation state without a second semantic completion.
* **Lease/fence.** Activation establishes the live owner and renews it. A fresh host takes over only after expiry and increments the authority/fence observed by all writes. Read-only reconstruction does not perform takeover.
* **Fork/rewind.** The selected source prefix is copied atomically within the destination partition; discarded suffix and source lineage remain retained. New work uses a fresh operation namespace. Cross-partition branch placement uses the external-child protocol instead of pretending the copy is atomic.

## Exact decisions required before final v1 cutover

1. Freeze the top-level v1 entity and wire schema for every map listed above. Separate semantic records from indexes and local delivery state; remove transitional broad `unknown` fields or assign each one a domain codec.
2. Freeze Session entry, parent/path, leaf-cursor, compaction, branch-lineage, and snapshot identity semantics. Decide where model/tool content is canonical and make mailbox/runtime projections reference or bounded-copy it without duplicating transcript authority.
3. Define codecs and identity rules for every `OperationKind`, especially pending input, result/error, model response, completed tool command/output, structured output, nested operation, send, wait, and program records. `commandId`, operation key, input digest, attempt, and resolution identity must survive reopen and branch copy.
4. Freeze journal receipt/head semantics: sequence, logical state digest, retained receipt lookup, conflict reconciliation, snapshot/replay bounds, and the exact publication retry boundary. The artifact receipt lookup seam in `journal.ts`/`runtime.ts` is currently under repair and is not a stable seam for new callers.
5. Freeze ownership and fencing for run/session execution, scheduler claims, workers, and external resources: owner ID, incarnation/generation, attempt/epoch, expiry, heartbeat/takeover, and stale-write rejection.
6. Freeze fork/rewind/program-branch reference rules, retained suffix/history, operation namespaces, Session lineage, model/interrupted response copying, and budget/cost reservation invariants.
7. Freeze artifact base/update/object-reference and append-receipt semantics, including retry after publication loss and branch isolation. Local artifact publication queues remain non-authoritative.
8. Define the cross-partition protocol: sender obligation, receiver admission, settlement, acknowledgement, retained discovery index, catalog-loss reconciliation, dedupe identity, and terminal failure evidence.
9. Implement secret-free executable, registration, instruction, capability, hook, and gate pins plus effective settings/control provenance. Pin values that must replay identically, and record any deliberately live policy input with its authorization evidence; do not silently regenerate either from the current host.
10. Implement the required provider request/result-reference, workspace/kernel continuity, bounded-job, authenticated-principal/tenant, client projection, and transport contracts. Do not create fake RuntimeState records for process-local or external facts, but do not claim these required contracts are durable until their implementations and evidence exist.
11. Freeze retention, replay, event-size, state-size, and object-store limits with an independent logical digest. Recovery must remain read-only and deterministic within those bounds, and retained slots/receipts needed for the complete prefix must not be deleted.

This inventory is ready to guide the next schema/cutover review only after the named pending runtime, compiler, Artifact, and cross-partition discovery evidence is rerun and recorded.
